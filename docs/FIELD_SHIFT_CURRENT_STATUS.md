# Field Shift — current implementation status

**Audit date:** 2026-11-15
**Purpose:** Technical status snapshot for review and NASA Space Apps presentation preparation.
**Scope:** Current workspace source code and existing reports were inspected. No application tests, database queries, external source requests, deployment checks, or browser interactions were run for this audit. This is an implementation audit, not a scientific or security certification.

## Executive summary

Field Shift is a working web prototype for choosing a farm point, exploring gridded environmental context, recording farmer-provided information, and reviewing source-linked crop-rotation scenarios. It combines an on-demand NASA POWER history service, a small curated crop-reference rules engine, an acquired subset of published FAO/IIASA GAEZ v5 categorical assessments, and an explicitly experimental supervised-model path.

The most defensible presentation is as an **evidence-aware exploration and planning prototype**, not as an agronomic recommendation system. The core planner is rule-based and reports conditional reference findings; it does not produce a validated suitability score, yield estimate, profit estimate, irrigation prescription, or proven rotation benefit. GAEZ classes are published modeled assessments, not Field Shift predictions or farm outcomes. Farmer entries remain unverified. NASA POWER provides gridded historical estimates rather than parcel measurements.

Machine-learning status needs especially careful wording. Genuine models were trained for research and all five crop candidates were rejected before independent final testing; there is no scientifically accepted model or validated predictive coverage. Separately, the current workspace has an **enabled experimental inference route** and local model artifacts marked unaccepted. It can run only as an explicitly warned, unvalidated experiment and may use disclosed estimated soil inputs. This path is not the accepted planner and is not safe for farming decisions. Some existing source-page and README copy still says no model was trained or that experimental predictions are unavailable; that copy is stale relative to the research records and current experimental endpoint.

This audit did not query PostgreSQL or the live application. Therefore, it does not claim current database row counts, confirm that the saved workflows serve successfully, or independently verify live upstream availability. Filesystem inspection found the local FAO GAEZ cache manifest and 28 selected raster files; this does not establish that the cache is persisted or provisioned in another environment.

## Product and user journey

1. **Start:** The landing page describes the distinction between environmental estimates, farmer-reported values, and draft or reference-based planning. Users can start an analysis, open saved farms, browse sources, or choose one of four geographic case-study points. Case studies are reference points, not validated farm centers.
2. **Select a point:** The location page offers OSM basemap clicks, Nominatim place search, manual latitude/longitude, and optional polygon drawing. It can also open the four case studies. The selected point and optional boundary are passed to the farm form; the boundary is stored as geometry but is not used for area-wide NASA or GAEZ aggregation.
3. **Create a profile:** Required fields include a farm name, location description, and current crop. The user can add crop history, area, soil type, profile pH and moisture, irrigation category, priority, water resources, water constraints, and other constraints. Optional blank values remain unknown; they are not filled with proxy values.
4. **Review the farm:** The overview presents the selected point and boundary, the environmental dashboard, profile values, optional soil measurement history, and a provenance view of resolved soil inputs. Users can edit the profile or open the rotation planner.
5. **Plan and save:** The planner shows current profile context and lets the farmer save two editable rotation drafts. Drafts are not assessed. A separate report form accepts an ordered current/planned sequence, previous crops, exclusions, a planning priority, an optional hypothetical date, an optional farmer-estimated seasonal water amount, and operational notes. It saves a versioned snapshot with conditional reference findings, three scenarios where supported, missing-information prompts, and source citations. The report can be reopened from its history.
6. **Review distinct evidence lanes:** The planner includes a separate FAO GAEZ crop/scenario lookup and a separately warned experimental ML workflow. Neither is a validated crop recommendation. The report snapshots GAEZ evidence and any experimental jobs available when it is generated; experimental outputs do not rank the rotation scenarios.

The application uses a signed, HTTP-only anonymous browser-session cookie to scope farm and report ownership. This is not account login: another browser does not share the workspace, and clearing the cookie can remove access to saved farms. No cross-device account or account-recovery flow is implemented.

## External-data coverage and provenance

### NASA POWER

- Current live retrieval requests daily AG parameters `T2M`, `T2M_MAX`, `T2M_MIN`, `PRECTOTCORR`, `RH2M`, `GWETTOP`, and `GWETROOT` from 2019-01-01 through 2025-12-31 for the selected exact point. Climate and wetness are separate product groups so a partial response can retain one group without inventing the other.
- The client checks UTC metadata, units, parameter presence, fill values, dates, and numeric validity; records retain the requested coordinate, returned geometry, source URL, retrieval time, and source classification. Conflicting stored observations are not overwritten. Caching uses exact coordinates rounded to five decimal places, not nearest-city substitution or an assumed POWER grid-cell identity.
- Historical uploaded study data cover four reference locations and seven years. `docs/PHASE_2_REPORT.md` records the original imported row counts and a separate real Paris upstream check; `docs/phase5/ENGINEERING_VERIFICATION.md` records a later real Córdoba retrieval and cache reuse check. These are dated historical evidence, not a check performed in this audit or a guarantee of current endpoint availability.
- Aggregates preserve missing values as gaps. Monthly temperature/humidity/wetness values are daily means, rainfall is summed, and annual means are day-weighted. Heat-day counts use daily maximum temperature above a threshold, not crop-specific damage. Anomaly baselines use complete matching periods from the available 2019–2025 record, not a 30-year climate normal. Seasonal DJF grouping is not a locally defined crop season.
- POWER wetness is a modeled dimensionless fraction: `GWETTOP` and `GWETROOT`. It is not SMAP, volumetric soil moisture, effective rainfall, or irrigation demand. No forecast or parcel-wide imagery is implemented.
- The climate CSV's original retrieval date and time standard were not embedded; its units were checked against NASA metadata, which does not authenticate the original file. Uploaded wetness is UTC, so daily climate/wetness co-alignment is not independently established.

### SoilGrids and farmer-provided evidence

- The ordinary environment dashboard has four exact-reference nearby SoilGrids estimates from the imported demonstration bundle, classified `PROXY_DEMO_ONLY`, at 0–5 cm. They retain original/sample coordinates, source offset, and provenance; the Al Ain source-distance discrepancy is preserved and flagged.
- These records are not a global SoilGrids query service. A new point with no exact stored estimate reports soil as unavailable rather than borrowing another study point. Soil texture, pH, organic carbon, and related static estimates are not current measurements of a farm.
- Separately, the experimental historical model-input builder accesses authenticated local research/source data for 2001–2020 preparation. Its optional soil-estimation policy can admit partial native coverage (at least 10% per layer) or use the nearest recorded training-cell soil means. It labels those inputs as estimated and warns that the original 95%-coverage training-input contract is not met. This is an experimental model input path—not a conversion of ordinary dashboard proxies into ground truth.
- Farmer profiles and measurement records remain their own evidence class. Values include date, depth, unit, and declared source where recorded. No independent lab verification is performed; sample location is not necessarily recorded.

### FAO GAEZ, ECOCROP, and other references

- The live GAEZ lookup uses the published categorical `RES05-SIX` class raster subset: GAEZ v5, 2001–2020 AgERA5, approximately 10 km at the equator, with seven crop types (wheat, barley, maize, soybean, chickpea, dryland rice, wetland rice) and four management scenarios (rain-fed/irrigated × low/high input). The inspected workspace has a manifest and all 28 selected raster files. The endpoint does not download layers during a public lookup; a missing/corrupt cache yields an unavailable result.
- A GAEZ class is a published model result, not a Field Shift model prediction, observed performance, probability, yield, or profit. It samples one raster cell at the selected point and does not represent all land in a drawn farm boundary. Irrigated/high-input scenarios do not establish that a farmer has that capacity.
- The rotation reference library is distinct: 13 selected ECOCROP species with source-attributed reference facts, plus FAO crop-water values for the subset with usable coverage and scoped conservation/rotation references. ECOCROP facts are expert estimates with uneven provenance; the source material identifies ECOCROP as historical/discontinued around 2015. No local crop trial validation is claimed.
- GAEZ, NASA POWER, SoilGrids, farmer entries, and the experimental model's estimates are not interchangeable data sources. The project does not use GAEZ classes as farm outcomes or as a validation set that proves Field Shift prediction accuracy.

### Services and network dependencies

The web flow depends on NASA POWER for uncached environmental points, OpenStreetMap tiles, and Nominatim for place search. GAEZ queries depend on the selected local raster cache. FAO/CGIAR/USDA source links are external references. An unavailable source should appear unavailable; it should not silently become another source or an example value.

## Actual machine-learning status

There are three separate facts to communicate:

1. **Research training happened.** Phase 4 and recovery records document genuine supervised training/evaluation against FAO/IIASA GAEZ v5 modeled suitability-index labels for five crop types (wheat, barley, maize, dryland rice, wetland rice). The expanded recovery record reports 215 aligned source cells and 1,075 crop-cell rows, with 135/45/35 environmental cells in training/validation/final-test partitions. Five crop rows per cell do not make five independent environmental locations.
2. **No model was scientifically accepted.** `docs/ml-recovery/REPORT.md` records that every crop failed support and/or accuracy gates before final testing; no final-test prediction was computed, no final test was consumed, and no accepted estimator was saved. The original model also failed geographic validation. Maize's global development metrics alone do not establish an accepted domain; only four development cells remained after a later support screen. No crop, country, or management domain has validated predictive coverage. The accepted-model status endpoint in `analysis/model.py` explicitly keeps predictions disabled.
3. **A separate experimental path is currently enabled.** Unlike the accepted-model endpoint, `experimental/policy.py` enables the warned experimental workflow. The local `generated-artifacts/experimental-ml/manifest.json` records five research artifacts, `productionAccepted: false`, `finalTestEvaluated: false`, and each crop as `rejected_before_test`. `experimental/routes.py` can execute an estimator after source preparation, and the user-facing panel allows a run after explicit acknowledgement. Results are labeled unvalidated and must not be used for real farming decisions. This is not scientific acceptance or a contradiction to the no-accepted-model conclusion.

The experimental model target is an approximation of the FAO/IIASA GAEZ v5 modeled all-land suitability index (0–10,000), not actual crop yield, profit, rotation benefit, or forecast weather. Its research contract uses historical 2001–2020 NASA POWER/MERRA2 climate features and ISRIC SoilGrids 0–5 cm area means at a GAEZ cell. The live dashboard's 2019–2025 point summaries and ordinary farmer/profile soil inputs do not automatically satisfy that contract. The experimental input builder separately retrieves/prepares the historical sources, refuses missing/invalid climate, and can apply the disclosed estimated-soil policy noted above. It never turns estimated inputs into validated data.

## Technical architecture and privacy boundaries

- **Frontend:** React, TypeScript, Vite, Tailwind, Wouter routing, TanStack Query, generated API client, Leaflet/React-Leaflet, and Recharts. The app routes include landing, location selection, farm list/create/view/edit, environment, four-region comparison, reference library, sources, and per-farm planner (`artifacts/field-shift/src/App.tsx`).
- **Backend:** Python FastAPI with Pydantic validation, SQLAlchemy, PostgreSQL JSONB models, Alembic history, and Uvicorn. The API artifact retains a Node launcher for the existing workspace commands; FastAPI serves application REST endpoints. OpenAPI contracts and frontend clients are generated from the API spec.
- **Persistence:** PostgreSQL holds farms, source registry, environmental locations/values, soil estimates, farmer measurements, import audits, manual strategies, and saved report snapshots. GAEZ rasters and experimental model/job files are local generated artifacts rather than PostgreSQL rows. The report does not establish whether those local files are persisted across a clean deployment/rebuild.
- **Ownership:** `SessionMiddleware` assigns a random owner ID to a signed anonymous session cookie. Farm, draft, measurement, report, GAEZ, and experimental routes check that farm against the cookie owner. This isolates browser workspaces but is not a named account or multi-device identity system.
- **Import controls:** The fixed-bundle ingestion path is operator-restricted. The ordinary browser is read-only for import audit; no public “become admin” route is implemented. Production schema/deployment state was not inspected or changed in this audit.
- **Request controls:** The code has input validation, cross-site write checks, request-size limits, NASA bounded retries/caching and exact-point locks, plus shared PostgreSQL admission controls described by `docs/phase5/ENGINEERING_VERIFICATION.md`. No load or saturation benchmark is documented.

### Known limitations and risks to communicate

- NASA POWER is gridded historical estimation; the dashboard does not show current weather, on-farm sensors, crop-stage stress, or satellite imagery.
- No parcel-wide aggregation is made from the optional polygon. GAEZ is a single cell; POWER is an exact requested point and is not treated as a known authoritative grid polygon.
- The dashboard's seven-year history is not a climate normal. Imported source metadata and daily alignment have documented uncertainty.
- SoilGrids proxy records cover only four demonstration coordinates in the ordinary soil lookup. They are not measurements, labels, or a globally available soil service.
- Crop library coverage is limited; local planting and harvest calendars, varieties, root-zone and soil-constraint screening, crop-stage water balance, and independent agronomist review are absent.
- The reference engine does not interpret free-text constraints, compute suitability scores, predict yields or profits, prove soil-health gains, prescribe irrigation, or establish causal rotation benefits.
- GAEZ covers only the seven selected crops, four scenarios, one period, and a coarse raster subset. The acquired cache is operator-provisioned/generated data and is not automatically guaranteed in a clean or published environment.
- The experimental inference lane is accessible when its current workflow flag and artifacts are available, despite all five models being rejected. Explicit user warnings do not convert it into safe or accepted advice. Avoid demonstrating numeric output as a result for a real farm.
- Anonymous cookie ownership lacks account recovery and cross-device sharing. Do not use personal or sensitive farm information in public demos.
- Existing source-page limitations and portions of README copy are stale: they state no model was trained/deployed and omit the current integrated GAEZ/experimental paths. See the next section.

## NASA Space Apps presentation description

**Field Shift is an evidence-aware farm exploration and crop-rotation planning prototype. Farmers can select a field point, examine NASA POWER's gridded 2019–2025 climate and modeled-wetness history, keep their own crop and soil observations separate from regional estimates, and compare a reported rotation with conditional source-based scenarios. A separate lookup can show published FAO/IIASA GAEZ v5 crop-suitability classes for a limited crop and management subset. Field Shift does not provide validated crop-suitability predictions, yield forecasts, irrigation prescriptions, or professional agronomic advice; its experimental ML outputs have failed scientific acceptance and are not safe for farming decisions.**

For a shorter spoken version: **“Field Shift helps farmers explore the evidence around a field before sketching crop rotations. It keeps NASA gridded climate context, farmer-reported information, published FAO assessments, and experimental research outputs visibly separate—so the prototype supports review rather than claiming an answer it has not validated.”**
